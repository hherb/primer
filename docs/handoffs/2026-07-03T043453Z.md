### The proven split recipe (fifth clean run this session)
1. Baseline: `cargo test -p <crate>` (with the right `--features` if tests are gated) green BEFORE touching anything; record the pass count.
2. Read the whole file; map natural responsibility boundaries.
3. Convert `foo.rs` → `foo/mod.rs` + siblings via `git mv foo.rs foo/mod.rs` (preserves history), then write the siblings. `mod.rs` keeps anything callers outside the new dir reach via unchanged paths (or re-exports it).
4. **Visibility across the new module boundary — five cases seen so far:**
   - Already-`pub mod` blocks (consts.rs, this session): trivial — one file per block, external paths unchanged, no re-exports, `tests.rs` untouched.
   - Private helpers/consts a *test child of the parent* reaches (`FALLBACK_LINE`, #318; `english_pack`, #321): keep them IN `mod.rs`.
   - A `pub(super)` method that *parent-level tests* call directly (`build_turn_prompt`, #320): re-declare as `pub(in crate::<parent-path>)` — same effective reach, test files stay untouched.
   - A private helper/type a *test child* reaches by bare name via `use super::*` but which now lives in a *sibling* submodule (`is_factual_question*`, `Passage`, #321): mark the item `pub(super)` in the submodule and add a `#[cfg(test)] use <submod>::<name>;` (PLAIN, not `pub(crate) use` — E0364) in `mod.rs`.
   - A helper whose only caller moves with it (`stream_inference_response`, #320): narrow to private.
5. Fix moved relative paths: prefer absolute `crate::…` imports (or `super::` for a re-exported sibling) in the new submodules. (`mod.rs` itself keeps plain `super::…` — its depth is unchanged.)
6. Verify: pub-surface diff empty (`grep -oE 'pub (struct|enum|fn|const|async fn|trait|type|mod) [A-Za-z_0-9]+' | sort -u`, old vs new — **include `mod` AND `type`**; beware doc-comment false positives like a literal `` `pub mod X` ``), crate suite count matches baseline, feature-combos clippy if cfg arms exist, full-workspace `cargo test`, clippy `-D warnings`, fmt `--check` (run fmt AFTER the split).

## Patterns to reuse, not reinvent

- **The 6-step split recipe above** — new (easiest) case this session: a file that is already N `pub mod X { … }` blocks splits mechanically one-file-per-block with ZERO visibility work and an untouched `tests.rs` (it reaches submodules by name via `super::<submod>`). Use `git mv foo.rs foo/mod.rs` so the rename shows as `R` not `D`+`A`.
- **Pub-surface diff must include `pub mod` AND `pub type`**. Full regex: `pub (struct|enum|fn|const|async fn|trait|type|mod) [A-Za-z_0-9]+`. **Watch for doc-comment false positives** — a `//!`/`///` line containing a literal like `` `pub mod X` `` will match; reword the doc or exclude comment lines. Note the regex deliberately does NOT match `pub(super)`/`pub(crate)` — those are internal.
- **Doc-drift hunt recipe:** after a split, grep the moved file's name AND its key symbols across README/ROADMAP/CLAUDE. This session: the only doc reference to update was the CLAUDE.md `primer-core` `consts` bullet; the lines-78–80 `consts.rs` hits were the *per-crate* files (classifier/extractor/comprehension) and stayed accurate.
- **Use ABSOLUTE paths for shell tools** — Bash cwd resets between calls. `git show <ref>:<path>` wants the repo-root-relative path (`src/crates/…`).
- **A grep final pipe stage returns exit 1 on zero matches** — a workspace-test command's exit 1 can just be a trailing `grep 'FAILED'` matching nothing (= success). Check the `test result:` / `Finished` lines, not the pipeline exit code.
- **Branch each PR off `main`, not off the previous branch.**
- **Run long cargo passes with `run_in_background: true`**; the harness notifies on completion — no polling needed. Do NOT chain `sleep`; the harness blocks foreground `sleep`.
